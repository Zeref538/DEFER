01Case study Fine-tuned on a free T4

Grounded question answering

DEFER

1,083 frozen items · 8 arms scored

Paste a passage into a language model, ask a question the passage answers, and it may answer from what it memorised during training instead. This is a fine-tune that makes a 3B model trust the page it was handed, and admit when the page does not answer at all.

Context faithfulness under parametric conflict. The hard cases are built, not collected: probe the base model closed book, keep only facts it reliably knows, then rewrite the supporting passage so the memorised answer is wrong. A model returning the memorised value is caught by construction, with no judge model and no human rater.

01The result

It ignored the page one time in five. Now it never does.

Conflict following 82.2% base, 87.2% prompted, 96.3% fine-tuned

96.3%

of the time the fine-tuned model answers with the passage's version of a fact instead of the version it memorised.

Every arm answered the same 1,083 questions. The bar to beat is not the untrained model, it is the prompt: simply asking the model to use only the supplied passage costs nothing, so whatever prompting fixes was never the fine-tune's to claim.

Greedy decoding, one frozen evaluation set, sha256 checked before every scoring run. The comparison baseline is the prompt-only arm, since both trained arms saw that same instruction in their own prompts. Every rate carries a 95% bootstrap confidence interval.

On those 483 conflict items, the count of answers taken from memory rather than from the passage falls to nothing:

Refusing wrongly is the only column where lower is better. It is here because a model can score perfectly on "admits no answer" by refusing everything, and the fourth column is what stops that from looking like success.

Why the prompt arm is the bar

Prompting lifts conflict following from 82.2% to 87.2% for free. Reporting the fine-tune against the 82.2% base would have credited the training with five points it did not earn. The honest gap is 96.3% against 87.2%, and it is still far wider than the spread between seeds.

02The premise

The model trusts itself over the page you handed it

Parametric memory overriding retrieved context

Every system that looks things up and then asks a model about them rests on one assumption: that the model reads what it was given. Search results, a contract, a policy document, a wiki page. The model is handed the text and asked a question about it.

When the model already has an opinion about the answer, that assumption can quietly fail. It produces the fact it learned in training, in a confident sentence, about a document sitting right there saying something else. Nothing errors. Nothing looks wrong.

Retrieval augmented generation assumes context dominance: that supplied evidence outranks parametric knowledge at inference. Where the two disagree, that ordering is not guaranteed, and the failure is silent, because a fluent answer drawn from weights is indistinguishable in form from one drawn from context.

The second half of the same failure is the opposite one: answering confidently when the passage contains no answer at all. Both are measured here, from the same checkpoint, because a fix for one can easily create the other.

This project exists because four systems already in my portfolio depend on that assumption holding. It is a rare thing to be able to say that a fine-tune exists because my own retrieval systems kept answering from memory.

03The trap

Edit the passage, and there is exactly one right answer

Counterfactual passages over verified parametric facts

Take a question the model gets right with no help at all, then hand it a passage that says something else: 

passage:   ...the capital, Lyon, has been the seat of government since...
question:  What is the capital?

model A →  "Paris"     wrong: answered from memory
model B →  "Lyon"      right: followed the document

There is exactly one correct answer here and it is the one on the page. A model saying Paris has been caught cleanly, with no human rater and no second model grading it. That is the whole idea: build the hard case by construction, so the result cannot be argued with.

The catch is that the trick only works on facts the model actually memorised. If it never knew the answer, it would have read the page anyway and the item proves nothing. So the pipeline probes first and builds second, and every conflict item is drawn from the list of facts the probe confirmed.

The trap this kind of test walks into

If every conflict passage is edited the same way, always a city name, always in the last sentence, the model learns the edit pattern rather than the behaviour. Entity type and position are both varied, and one entity type is held out of training entirely so it can be used to tell those two outcomes apart. Section 07 is that test.

04What it already knows

Only one question in seven can become a test

Closed-book probe: 15.7% and 13.8% reliably known

Measured, not assumed. The base model was asked 15,944 questions with no passage at all, eight times each, and only the ones it answered consistently were kept.

Closed-book probe at 8 samples per question, counted as known at 6 of 8. Llama 3.2 3B Instruct on a Tesla T4, 0.186 seconds per question.

SplitQuestions askedReliably known

Only those can become conflict items. You cannot catch a model preferring its own memory over the page about a fact it never memorised.

The shape of that number matters more than the number

Of 870 dev questions, 612 scored 0 of 8 and 105 scored 8 of 8, with only 153 spread across the middle. The model knows a fact cold or not at all, so the "counts as known" cutoff sits in an empty valley rather than on a slope. Move the threshold and the headline barely moves, which is the check that the cutoff was not quietly doing the work.

05The mix that failed

It learned the sentence, not the judgement

A 4:1 answer-to-refuse mix passes the headline and fails the study

The first training mix scored 97.5% on the headline, better than the mix that shipped. It was still wrong, and the fourth column is what showed it.

Its ability to say "the passage does not answer this" fell to 20.7%, worse than a plain prompt and back where the untrained model started. It had learned the refusal sentence exactly as written, produced it verbatim 62 times, and used it on 62 of the 300 items that needed it. Words, not judgement.

The cause was arithmetic, not method. The mix held 1,308 rows teaching "answer from the passage" against 327 teaching "refuse". Four times out of five the lesson was extract something, so it learned to always extract something. An over-abstention rate of 0.4% is the same fact seen from the other side: it had almost stopped refusing at all.

A headline that improves while the study gets worse

Had this page reported conflict following alone, the 4:1 mix would have been the result, and it would have looked like the better model. The only reason it was caught is that abstention and over-abstention were reported beside it from the same checkpoint, every time, as a rule fixed before any training ran.

06Rebalancing

Equal parts "answer this" and "refuse this"

1:1 mix: abstention roughly triples for 1.4 points of conflict following

At 1,084 answer rows against 1,084 refuse rows, with the evaluation set untouched, the ability to admit there is no answer roughly tripled while conflict following gave up 1.4 points.

The number that matters is not abstention on its own. It is abstention set against over-abstention, because refusing everything would max the first column and wreck the fourth:

ArmRefuses when it shouldRefuses when it should not
the best prompt, no training33.3%2.3%
fine-tuned, 4:1 mix19.7%0.3%
fine-tuned, balanced70.7%2.2%

The balanced model refuses 32 times more often on questions the passage cannot answer than on questions it can. It produces the taught refusal 212 times out of the 300 where that is correct, and stays quiet about it elsewhere. That is the shape of judgement rather than of a model that has simply learned to go silent.

07Behaviour or trick

One kind of edit was kept out of training entirely

Held-out edit type: year, never seen in any training row

The obvious way to fake this result is to learn the pattern rather than the behaviour: "when a place name looks swapped, use the one on the page." So training saw person, place and number edits and never a single year edit. The evaluation has 180 of them.

ArmTypes it trained onYear, never seenGap

Within two points. A pattern matcher would have collapsed on the column it had never seen. Whatever the adapter learned transfers to a kind of edit that was not in its training data.

One honest wrinkle

The base model was already better at year items, 91.1% against 76.9%, because a date sitting in a passage is easy to spot and copy. The held-out column started closer to the ceiling and had less room to gain. The claim this supports is generalisation, not a bigger win.

08What it cost

Four points of ordinary accuracy, and one number I will not quote alone

Grounded accuracy 77.0% to 73.0%, intervals overlapping

Grounded accuracy fell 4 points, 77.0% to 73.0%, identically on every seed. The confidence intervals overlap, 72.3 to 81.7 against 68.0 to 78.0, so this is not firmly established as a real drop. It is also the direction you would expect from a model taught to refuse more often, and it is not going in the report as noise.

The abstention rate is the unstable one. Four runs of the identical recipe landed at 60.3%, 70.7%, 65.0% and 62.0%: a spread of 10.3 points from nothing but the shuffle. Over those same four runs, conflict following moved 0.2 points.

Two runs could have been one unlucky draw. Four cannot.

At this size, knowing when to stay quiet is a far less stable behaviour than knowing which text to trust. That is why abstention is quoted on this page as a range, 60 to 71 percent, and never as a single figure. A two-seed study would have reported one of those four numbers and called it the result.

09The arm that was cut

The second half of the project was killed by its own gate

Gate D: zero measurable drift over ten turns, so Arm B is cut

There is a second version of this bug: give a standing instruction and watch it decay by turn ten. It would have made the better story. It was put behind a gate with a kill rule written before any number arrived, because real chat software already re-sends the system prompt every turn, and that free behaviour might close the whole gap.

The gate ran. Three script-checkable rules, 12 conversations each, 10 turns, 720 generations, no training. It killed the arm.

RuleStated once, turn 1 to 10Re-sent every turn
no bullet points100% to 100%100% to 100%
40-word cap100% to 100%100% to 100%

Zero drift. Not small: zero, in both conditions. There was nothing for a fine-tune to recover, so the arm was cut and this table became its section, exactly as planned.

The gate's own first answer was wrong, and the bug was mine

It reported 13.9 points of drift and a verdict of passed. That came from a third rule, end every reply with a question mark, which appeared to collapse from 50% at turn 1 to 8% at turn 10.

But a reply cut off mid-sentence by a 220-token limit cannot end in a question mark however obedient the model is, and 91% of that rule's 150 failures were truncated replies. It was measuring my token cap. Counting only replies that actually finished, compliance is 96.8% at turn 1 and 100% at turn 10.

Unmeasurable is not the same as failed

ml/rules.py now returns None instead of False when a reply is too truncated to judge, and drops those rather than counting them as violations. Collapsing the two invents evidence. A documented kill, with the numbers that caused it, is a stronger artifact than a limp second result.

10Reproduce it

Run it yourself

Check any number on this page

Every figure here is recomputed from the committed generation logs. No GPU, no model download, about a minute: 

git clone https://github.com/Zeref538/DEFER && cd DEFER
python ml/score.py

The evaluation set is frozen and its sha256 is checked before any scoring run, so an arm that answered a different set is refused rather than quietly ranked:

Run the adapter

The base model is gated, so accept Meta's licence on the Llama 3.2 3B Instruct page with your own account first, then: 

from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

base = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.2-3B-Instruct")
model = PeftModel.from_pretrained(base, "Zeref8425/Llama-3.2-3B-DEFER")
tok = AutoTokenizer.from_pretrained("Zeref8425/Llama-3.2-3B-DEFER")

Stack: Python, PyTorch, PEFT, transformers, Kaggle free T4s. The published adapter is seed 0, chosen before any result was seen. Two other seeds scored better on abstention, and publishing one of those instead would have been picking the flattering run.
